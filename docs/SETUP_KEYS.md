# Настройка ключей и LoRA — Game2 v0.21.3

## Где ключи

**НЕ** вставляйте OpenAI и WaveSpeed ключи в `src/`, `index.html`, `.env` фронтенда или GitHub. В используемой архитектуре React-клиент обращается к Cloudflare Worker, а он уже вызывает OpenAI / WaveSpeed. Worker читает ключи из `env`.

Когда решите развернуть новую версию:

1. Откройте [Cloudflare Dashboard](https://dash.cloudflare.com/) → **Workers & Pages** → нужный Worker → **Settings** → **Variables and Secrets** → **Add**.
2. Добавьте тип **Secret**, имя `OPENAI_API_KEY`, значение — API-ключ OpenAI.
3. Добавьте тип **Secret**, имя `WAVESPEED_API_KEY`, значение — API-ключ WaveSpeed.
4. Рекомендуется третий Secret: `PHOTO_SIGNING_KEY`, произвольная длинная случайная строка для подписывания GPT-решений о фото. При отсутствии ключа код использует `OPENAI_API_KEY` как ключ подписи (работает, но хуже с точки зрения ротации ключей).
5. Опционально `OPENAI_TEXT_MODEL` — название совместимой модели OpenAI Responses API, если требуется заменить модель по умолчанию.
6. В Cloudflare используйте **Deploy** для применения изменений. При будущей публикации обновлённый `cloudflare/worker.js` нужно загрузить отдельно от клиентских файлов.

## LoRA Александры

Ссылка уже указана **только в `cloudflare/worker.js`**, как серверный fallback:

```text

```

При необходимости добавьте **Secret** `ALEXANDRA_LORA_URL` с новой ссылкой — он имеет приоритет над встроенной. Другие параметры: модель `wavespeed-ai/z-image/turbo-lora`, trigger `g2girl01`, `ALEXANDRA_LORA_SCALE` (по умолчанию `0.85`), размер `1024*1536`, случайный seed `-1`.

Фотографии появляются **только в переписке**, если GPT принял решение отправить фото. Больше нет фоновой генерации фотографий при запуске или отдельного маршрута «Рядом». Неактивные старые провайдеры сохранены в исходнике Worker для возможного последующего использования, но не используются в новом маршруте чата.

## Firebase и публикация

Для фронтенда пример конфигурации — `.env.example` в корне (Vite/Firebase). Это **не** место для секретных ключей провайдеров. Сохранённый `VITE_CLOUD_LANGUAGE_ENDPOINT` позволяет указать адрес Cloudflare Worker, если используется не встроенный endpoint.

Ничего не отправлялось в GitHub/Cloudflare/Firebase и никаких API-запросов на генерацию при подготовке архива не выполнялось.

## Прототип виртуальной экономики

Формат состояния персонажей (`SCHEMA_VERSION=4`) не менялся. Отдельные документы пользователя: `users/{uid}/player/profile` и `users/{uid}/player/economy`.

Начальный демонстрационный баланс — 3000 монет. Подарки и переводы списываются атомарной Firebase-транзакцией и пишутся в журнал. Для локальной разработки без Firebase используется localStorage. **Текущие общие правила Firestore позволяют пользователю менять собственный документ кошелька** — это приемлемо только для игровой демонстрации. Для продажи валюты, античита, покупки за реальные деньги и переводов между живыми пользователями потребуется серверный авторитетный кошелёк, правила доступа только для чтения и серверная книга операций.

Включение флага «Показывать анкету другим персонажам» только сохраняет настройку. **Автоматическое знакомство, заинтересованность персонажей и первые сообщения на основе профиля ещё не подключены**. Для этого понадобится отдельный серверный маршрут discovery/initiative и публичный профиль с явно заданным кругом видимости. Сейчас личный документ профиля доступен лишь своему Firebase UID.
