# Game2 v0.21.8 — Alexandra · Chat Reliability & Wardrobe

Накопительное обновление поверх `v0.21.11`. **Рабочая база — только этот архив, не старый GitHub и не отдельный патч.**

## Интерфейс

- **Чат:** основной существующий GPT-first диалог и фотогенерация через WaveSpeed Z-Image Turbo + LoRA. Не изменено состояние эмоций, границ, памяти и отношений.
- **Люди:** реестр персонажей (пока Александра), переход к отдельному чату, оплата виртуальных подарков и переводов. В будущих версиях добавление записей в `characterProfiles` расширит список; у движка уже есть привязка истории к `characterId`.
- **Соцсеть:** лента Александры + карточка пользователя и переход в его профиль. Контент пока статический.
- **Мой профиль:** имя, username, био, город, интересы, статус, HTTPS-аватар, цвет обложки, opt-in к будущим знакомствам, просмотр кошелька и операций.

Удалены экран «Рядом», его клиентская генерация/локальный кэш и endpoint `/alexandraPresencePhoto` из нового Worker. Никаких фото при входе в приложение. Фотографии по инициативе/решению GPT в чате остались.

## Деньги

Стартовый тестовый баланс — 3000 **виртуальных** монет. Подарки (кофе, цветы, книга, наушники) и переводы (100 / 500 / 1000) записываются отдельно от механической системы чувств. Оплата не гарантирует симпатии. Сообщение о виртуальном событии передаётся в диалог, на которое девушка реагирует по собственному характеру.

Платных пополнений и покупок за реальные деньги **нет**. Текущий кошелёк — прототип, не защищённый от модификации собственных документов через Firebase SDK. Перед вводом реальной экономики необходим серверный ledger.

## v0.21.9 — Firestore timeout / retries

Устранён ложный обрыв любого запроса к Firestore спустя 8 секунд. Важно: серверные транзакции нельзя отменять через `Promise.race`/клиентский таймер — они могут продолжить выполняться и конфликтовать с повторной отправкой. Сейчас ограничения применяются только к заведомо читающим операциям (30 секунд), а записи ожидают фактического результата SDK в пределах общего контроллера отправки.

При временном `unavailable` больше не запускается повторный полный bootstrap. Полную пересинхронизацию выполняем только при конфликте revision. Ошибки теперь указывают конкретную операцию Firestore, а в настройках виден номер сборки.

**Ограничение:** без логов Firebase из реального браузера нельзя подтвердить, что исчезнут все сетевые ошибки: Firestore SDK может действительно получать `unavailable` от сервиса/транспорта. Релиз убирает доказанный дефект 8-секундного ожидания и лишние запросы при повторах, но не подменяет реальную диагностику сетевого транспорта.

## v0.21.16 — согласование фото и восстановление сообщений

- Текст ответа GPT больше не подтверждает отправку фото сам по себе: для этого требуется `photoDecision` с допустимым подписанным промптом. Необеспеченные обещания фото заменяются честным статусом.
- Для одобренного фото с пустым промптом предусмотрена дополнительная подготовка промпта до подписания.
- В Worker различаются проблемы Firebase Auth и App Check (`401`), а недоступность сервисов проверки выдаётся как временная ошибка (`503`), без бессмысленных запросов на обновление неправильного токена.
- Сбой необязательной записи состояния близости после успешного `commitTurn` не помечает уже сохранённый ответ неотправленным.
- Неотправленные ходы сохраняются локально под тем же ID и восстанавливаются после перезапуска; ручная кнопка повтора не создаёт нового хода. Журнал очищается после подтверждения ответа, пропуска и очистки диалога.
- После неудачного сообщения клиент не запускает немедленную конкурирующую синхронизацию Firestore.
- Схема Firestore и формат истории не изменены (`SCHEMA_VERSION = 4`).

См. `RELEASE_v0.21.16.md`.
